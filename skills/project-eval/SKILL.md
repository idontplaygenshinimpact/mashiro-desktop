# project-eval：项目全面评估

## 何时使用

用户说以下任一触发：
- "评估 XX 项目 / 全面评估一下项目"
- "这个项目有什么问题 / 代码质量怎么样"
- "帮我做一次项目体检"

## 使用流程

1. **确认项目**：调 `skill__project_eval__evaluate_project`（project=项目名——personal_projects 配置中的 name）
2. **生成报告**：工具读项目全部核心源码（排除测试/配置——核心目录优先）→ subagent 串行分析（源码要点）→ **分步评估 8 维度**（架构/代码质量/测试/安全/性能/可维护性/技术债/风险——每维度单独 subagent——详细）→ 汇总（总评/问题清单/亮点/Top 5）→ **打磨循环**（评审/修正——上下文累积——不缩水）→ 存档 `output/project-evals/项目·xxx-评估报告.md`
3. **查看报告**：总评（评分 1-10）+ 8 维度评估（现状/问题/建议——引用具体文件/函数）+ 问题清单（按严重度排序）+ 亮点 + Top 5 改进
4. **重新评估**：用户说"重新评估" → force=true

## 纪律

- **只基于真实源码**——不编造——引用具体文件/函数/行号
- **问题要具体**（不是"代码质量一般"——是"xxx 函数重复实现 3 次——建议抽象"）
- **平衡**（不只挑刺——亮点也要——评估客观）
- **建议可落地**（不是"优化性能"——是"xxx 处用 memo 避免重渲染——预计收益"）
- **打磨循环**（评审对照质量标准清单——修正只补差距不缩水——上下文累积）
