# subagent 打磨质量工单 v2（对照常见 subagent 设计——多轮打磨 + 上下文累积 + 角色分离）

> 背景：标杆文档（D:\ai-career\docs\interview-prep.md——98504 字符——人工/多轮打磨）。当前 subagent（runSubagent）是**一次性执行器**（task + context → 一次生成 → 结束）——没有上下文累积、没有反馈循环、没有评审——生成 28728 字符（3.4 倍差距）——不严格算 agent。用户要求：**升级 subagent——对照常见 subagent 的设计**（Claude Code/通用 agent 框架的 subagent）：**有上下文（多轮对话）/ 反馈循环（生成→评审→修正→再评审）/ 角色分离（生成者/评审者/修正者）**——多轮打磨达到标杆质量。

---

## 一、常见 subagent 设计对照（升级目标）

| 常见设计 | 说明 | 当前（缺） | 升级后 |
|---|---|---|---|
| **有上下文** | 多轮对话——subagent 能"看到"自己之前的输出——不是单次调用 | ❌ 单次调用（task+context） | ✅ 每轮带上次全文（上下文累积——越改越准） |
| **反馈循环** | 生成 → 评审 → 修正 → 再评审——达标才结束 | ❌ 一次生成就结束 | ✅ 评审/修正循环（最多 3 轮——每轮评审结论） |
| **角色分离** | 生成者/评审者/修正者——专业分工（各司其职） | ❌ 单一生成者 | ✅ 三个角色（生成者/评审者/修正者——prompt 各不同） |
| **质量标准** | 评审对照清单——逐项打勾——达标信号明确 | ❌ 无评审 | ✅ 质量标准清单（评审逐项对照——输出达标/不达标结论） |
| **few-shot 示例** | prompt 给标杆片段做示例——模型模仿标杆风格/深度 | ❌ 纯描述 | ✅ 生成/修正 prompt 嵌入标杆片段示例 |

## 二、升级后的 subagent 流程（多轮打磨循环）

```
round 0（生成者）：分步生成草稿（开场/源码要点/八股/拷打问答/怎么讲——汇总拼接）
  → 存档草稿（上下文累积起点）
round 1（评审者）：对照质量标准清单——找差距（缺什么/哪里浅/哪里不是讲人话/哪里不真实）
  → 输出差距清单（作为下轮上下文）
round 2（修正者）：带【上次完整文档 + 评审差距清单】——逐项补全/深化/打磨——输出修正版
  → 存档修正版（上下文累积）
round 3（评审者）：再对照清单——达标？→ 存档最终版；不达标 → 输出新差距清单
  → 再修正（round 4……最多 3 轮修正——每轮带上次全文 + 评审结论）
最终：达标版存档 output/interview-prep/项目·xxx-面试准备.md
```

## 三、实现任务

### 任务 1：生成者（round 0）

```
分步生成（现有 skill.mjs 保留）：开场/源码要点/八股/拷打问答/怎么讲——5 个子生成
**加 few-shot**：生成 prompt 嵌入标杆片段示例（八股示例/讲人话示例/拷打示例——从
  D:\ai-career\docs\interview-prep.md 取 3-5 段——模型模仿标杆风格/深度）
→ 汇总拼接 → 草稿存档
```

### 任务 2：评审者（round 1/3）

```
新增【评审者 subagent】：
- role: 严格的质量评审员（对照质量标准清单逐项打勾）
- 任务：读草稿 → 对照清单 → 输出差距清单（缺什么/哪里浅/哪里不是讲人话/哪里不真实）
- 输出格式：达标/不达标结论 + 差距清单（每条：问题 → 位置 → 怎么补）
- 带上下文：草稿全文（评审者看得到完整内容——不是片段）
```

### 任务 3：修正者（round 2/4）

```
新增【修正者 subagent】：
- role: 资深面试辅导老师（打磨者）
- 任务：带【草稿全文 + 评审差距清单】→ 逐项补全/深化/打磨 → 输出完整修正版
  （不是增量——是整篇打磨后的版本——上下文累积：看得到原文和差距）
- few-shot：修正时对照标杆片段示例（模仿深度/讲人话）
- 红线：不编造文件名/代码——只引用真实源码
```

### 任务 4：循环控制（skill.mjs）

```
for (let round = 0; round < 3; round++) {
  评审（带当前文档）→ 达标？→ break 存档
  修正（带当前文档 + 差距清单）→ 新文档
}
存档最终版 + 返回 summary（轮数/每轮评审结论/最终字符数）
```

### 任务 5：few-shot 示例库

```
从 D:\ai-career\docs\interview-prep.md 提取标杆片段（八股示例/拷打问答示例/讲述脚本示例/
讲人话示例——各 1-2 段）——嵌入生成/修正 prompt——模型模仿标杆
（存 skills/interview-prep/examples.md——或直接从标杆文档读取）
```

## 四、质量标准清单（评审逐项对照）

```
□ 背诵路线图（1 天/3 天/1 周） □ 一句话定位（口语化可背）
□ 关键设计决策速览（5-8 条讲透） □ 源码要点（核心文件 300-500 字/其他速览）
□ 八股（原理 300-500 字/项目用法/面试应答（口语化可背）/追问 2-3 个带答案）
□ 拷打问答（每文件/知识点/决策——完整答案可背）
□ 可能的追问（每八股/模块 2-3 个） □ 怎么讲（三层讲述法/讲述脚本/技巧）
□ 讲人话（口语化——可直接背诵——不是书面语/提纲）
□ 真实源码（不编造文件名/代码）
```

## 五、验收

- [ ] 多轮打磨循环（生成 → 评审 → 修正 → 再评审——至少 1 轮完整循环）
- [ ] 上下文累积（修正轮带上次完整文档 + 评审结论——不是单次调用）
- [ ] 角色分离（生成者/评审者/修正者——prompt 各不同——职责清晰）
- [ ] few-shot 示例（生成/修正 prompt 嵌入标杆片段——模型模仿）
- [ ] 生成文档 ≥50000 字符（接近标杆 98504）
- [ ] 结构全覆盖（质量标准清单全勾——含可能的追问/讲述技巧）
- [ ] 讲人话（抽样读像面试应答不像笔记）
- [ ] `npm test` 全绿 + lint 0 + typecheck 0

## 六、红线

1. **真实源码**（不编造文件名/代码——修正轮不引入编造）
2. **八股准确**（原理/对比/追问——不幻觉）
3. 评审/修正必须带上下文（上次全文 + 差距清单——不允许"盲改"）
4. 轮数上限 3（每轮有评审结论——不无限打磨）
5. few-shot 示例只作风格/深度参考——内容必须基于本项目真实源码（防照搬别项目内容）

- 任务 3（修正者）：半天

## 八、面试价值

> "一次生成的文档和人工打磨的标杆差 3.4 倍——根因是 subagent 设计成'一次性执行器'（无上下文/无反馈）——**不严格算 agent**。升级对照常见 subagent 设计：**有上下文（每轮带上次全文——越改越准）/ 反馈循环（生成→评审→修正→再评审——达标才结束）/ 角色分离（生成者/评审者/修正者）/ few-shot 示例（模型模仿标杆）**。**'agent'和'一次 LLM 调用'的区别就是上下文和反馈循环——没有这两样，再强的模型也打磨不出质量。**"
