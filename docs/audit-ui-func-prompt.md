## 第一部分 · 功能闭环审计（重点，占报告篇幅 60%）

### 0. 闭环模型：九连环判定法
对**每一个**有状态、有产出的功能，按以下 9 环逐环打勾（✅/⚠️/❌），并指出断环位置与证据：

| 环 | 判定问题 |
|---|---|
| C1 入口可达 | UI 入口存在且文案/图标与真实能力匹配；隐藏入口是否还有别的路径（右键菜单、设置项、快捷键） |
| C2 执行可推进 | 有明确状态机（idle/running/…/done/error），每步状态可查询、可推进；不存在"执行中但无后续"的分支 |
| C3 过程可感知 | 进行中有进度/步骤/轮次反馈，长任务可取消或至少可中断 |
| C4 结果可产出 | 终止条件明确（自然结束/用户结束/异常结束），产出物完整（报告/列表/文件字段齐全、无占位符） |
| C5 结果可持久化 | 原子写入、崩溃可恢复（对照 atomic-json/db.mjs）；写失败有回滚或重试 |
| C6 历史可回溯 | 完成后可以从历史/列表再次查看、筛选、导出或删除；重启后仍在 |
| C7 产出可复用 | 产出被下游功能消费（数据血缘清晰）；同一数据多处存在时更新能传播，不会互相覆盖 |
| C8 异常可恢复 | 中断/失败/崩溃后：可重试、可续跑、可恢复现场；不产生"幽灵状态"（UI 显示进行中但任务已死、或反之） |
| C9 终态可清理 | 结束后 session/定时器/子进程/临时文件被清理，UI 复位，可再次进入；重复进入不冲突 |

### 1. 已知闭环链走查（逐条按九连环验证，缺一环即缺陷）
a) **模拟面试主闭环**：面板「开始模拟面试」→ `interview:start` → 逐轮答题 `interview:answer`（followup/new/stage 状态机、weak_hit 命中队列、答错分数阈值）→ 结束（LLM finish / 提前结束 / MAX_ROUNDS / 自动加试）→ `interview:end` 生成复盘报告 → 薄弱点回流 memory.addWeakPoint → 历史 `/api/interview/history` → 弱项进入学习清单（resume-plan-btn / addCard）→ `review:due` 到期复习 → `review:submit` → mastery 掌握度更新 → 下一次 `start` 时 get_weak_points 再次命中。
   必查断环点：面试进行中用户关面板/重启应用，session 是否残留导致下次 start 报"已有一场面试进行中"；答完最后一轮但 LLM finish 解析失败能否正常收尾；end 失败但 rounds 已落库（半场数据）；复盘报告是否可回看（UI 有入口吗）；薄弱点写入后 UI 是否有可见反馈；学习清单卡与薄弱点、复习卡三者状态是否会失同步（一处答对，另两处仍显示待办）。
b) **学习清单闭环**：清单生成 → 知识点学习（study-detail 流式）→ 追加/巩固（append/consolidate/cluster）→ 完成标记 `study-check` → 复习计划调度 → 到期提醒 → `review:submit` 评级 → mastery 更新。
   必查断环点：卡 stuck 在"学习中"有无超时；check=done 之后有无下一步引导；convolidate 后原卡与聚合卡的关系；生成失败有重试入口吗。
c) **求职闭环**：岗位发现/discover → 收藏（jobs）→ 投递记录 → 状态流转（投了/面试/Offer/拒）→ job-reminders 提醒 → 面试邀约与面试记录打通 → 结果反馈回写（大厂进度同步）。
   必查断环点：收藏后可不可以从简历/面试侧反向引用；状态流转是否有非法跳转；提醒触发后"已处理"如何消掉。
d) **巡检/定时任务闭环**：patrol 配置（设置抽屉）→ scheduler 调度注册 → 定时执行 → 结果落盘 → 通知（notify/win-toast/气泡）→ 失败重试/补跑 → 日志可查。
   必查断环点：配置修改后调度是否重建（改了不生效）；任务抛错是否静默；重复注册/僵尸任务；通知点击后能否跳转到结果。
e) **对话闭环**：发消息 → 流式返回 ←→ 历史持久化 → 会话列表/切换/删除 → 断流重连与续传（__streamToken）→ 删除会话后消息表是否残留。
f) **语音闭环**：语音开关 → 录音（vad/pcm-worklet）→ 识别（speech）→ 文本回显进输入框/直接发送 → TTS 播报（音量/打断/停止）→ 设备不可用降级。
g) **设置闭环**：每一项（方向/简历/邮箱/巡检/桌宠/数据维护/RAG）改完 → 保存确认 → 立即生效 → 重启后仍在 → 配置损坏是否有兜底与自愈。
h) **文件与输出闭环**：简历上传/导入（.txt/.md/.json/.docx/.pdf 解析）→ 内容进入面试准备 → 产出物写入 `output/` → 可打开/可导出/可回看 → 重复导入幂等。

### 2. 状态机与幽灵状态专项
对每个长流程，列出完整状态转移表：`状态 | 触发 | UI 表现 | 终态可达性`。专门找：
- 用户中途关闭面板/重启/退出后，流程卡在中间态（幽灵状态）且无恢复入口
- 双开/重复点击导致的重复执行（重复面试、重复任务、重复通知）
- 状态已终态但 UI 仍显示进行中（或反之）——即"UI 状态"与"数据状态"脱钩
- 僵尸任务：scheduler 注册了但 handler 已不存在/抛错静默吞掉
- 定时任务时间语义（时区、跨天、错过窗口后的补跑）

### 3. 数据血缘与一致性专项
- 同一知识点在 薄弱点(memory) / 学习卡(study) / 复习卡(review) / mastery / 面试 weakQueue 多处出现的更新传播链路；一处答对后其余处的状态（trace 一下写路径）
- 写入幂等性（re-enter/重复提交不以追加重复数据）；删除语义（删会话/删卡是否级联干净）
- atomic write 失败/中断后的恢复路径是否真实存在（对照 lib/atomic-json.mjs 用法）
- 产出物（复盘报告、学习笔记、output/*.md）格式完整、名字唯一、可被环节 C6/C7 消费

### 4. 跨功能用户旅程图（串联审计）
画出 3 条端到端旅程，标注每一步的起点文件与终点文件，检查衔接处：
- 旅程 A：模拟面试暴露弱项 → 学习清单补强 → 复习 → 掌握度提升 → 二次面试针对性命中
- 旅程 B：岗位发现 → 收藏 → 投递 → 提醒 → 面试 → 面试记录 → 复盘
- 旅程 C：今天打开应用（问候/巡检/复习提醒触发）→ 处理每一项 → 状态全部归零/可查

## 第二部分 · UI 审计维度（占 30%）
按界面面逐项检查，主要界面：① 桌宠本体（拖拽/菜单/气泡/表情/模型切换）② 面板顶栏（设置⚙️/重启♻️/语音🔊/刷新🔄）③ 页签：模拟面试/学习/求职/对话 ④ 设置抽屉 ⑤ 审批条与 ask-bar ⑥ 系统通知。
1. **布局层级**：溢出/遮挡/z-index 混乱；小窗口（≤800×600）与大屏表现
2. **视觉一致性**：颜色/字号/圆角/间距/图标统一；写死的散落颜色；深浅色场景
3. **状态覆盖**：每按钮 hover/active/disabled/loading/empty/error 六态；**重点：loading 态与后端真实状态是否一致（配合幽灵状态专项）**
4. **交互反馈**：长任务进度与取消入口；错误可读提示而非静默
5. **可访问性**：title/aria-label、键盘焦点、对比度
6. **文案**：通顺、与真实行为一致（"开始模拟面试"点了到底发不发生）
7. **性能**：面板切换/长列表/Live2D 卡顿；定时器/监听/资源泄漏
8. **安全与 CSP**：Node API 泄漏、'unsafe-eval' 必要性、IPC 输入校验

## 第三部分 · 非闭环性质的常规质量（占 10%）
断网与 widget 服务不可达的表现；非法/超大文件上传；无音频设备；日志可诊断性；e2e 覆盖缺口。

## 执行方法
1. 通读代码，建立「功能流 × 九环」矩阵与「UI 面 × IPC 通道」对照表。
2. 每个功能先静态分析九环，再 `npm run` 实测补证据（重点实测：中断恢复、重启后续传、双开、断链处）。
3. 出发点是**找断环**，不是找 bug 就完事——每条缺陷都要回答"环断在哪、断的原因、接上的最小改法"。
