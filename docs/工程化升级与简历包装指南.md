## 三、Monorepo 迁移要点（Phase 1，最容易踩坑）

1. **包拆分**（保持文件原地，用 workspace 软链，不物理大搬）：
   - `packages/core` ← `lib/`（业务逻辑，含 routes/tools）
   - `packages/contracts` ← 新增：zod schemas + 类型（Phase 2 时建）
   - `apps/desktop` ← `desktop/` + `widget.mjs`（electron 主进程 + 渲染层）
   - `apps/mcp` ← `mcp-server.mjs` + `bin/`
   - `packages/ui` ← `desktop/renderer` 的样式与组件（可选）
   - 根：scripts/tests 保留在根或移入 `apps/desktop`
2. **依赖提升与 Electron 坑**：electron/electron-builder 放根 devDependencies；`pnpm.onlyBuiltDependencies` 白名单（sherpa-onnx-node、koffi、live2d 原生模块需要 build script）；`node-linker=hoisted` 可减少兼容问题（MCP SDK 等对 pnpm 严格隔离敏感的包）。
3. **Turborepo pipeline**：`test`（依赖 typecheck）、`lint`、`build`（依赖 test 通过）、`bench`；缓存 `node_modules/.cache/turbo`，CI 命中缓存显著提速。
4. **imports 别名改造**：现有 `#lib/*`、`#root/*`（package.json imports 字段）→ 替换为 workspace 包引用，用 codemod 脚本批量替换（我们 scripts/ 里有大量一次性迁移脚本先例，可照做）。
5. **验证**：`turbo run test` 全绿 + `npm run dist` 出包 + `npm run e2e` 通过后才算迁移成功；CI 切 pnpm（`pnpm/action-setup`）。

## 四、包装方法论

### 4.1 学 CSISIP 的修辞结构（逐条拆解）

每条都是固定三段式：
```
做了什么（技术名词密度高） → 怎么做的（机制细节 2~3 个） → 效果（量化/质化收尾）
```
例：`设计「前端应用 — Supabase OAuth Server — IDP」三层标准化授权链路，独立封装 OAuth 提供认证能力…在前端应用层实现由守卫 + session 状态管理完整闭环，包括授权码交换、State 防 CSRF、localStorage 持久化、会话令牌安全传输`
= 架构图一句话 + 机制名词串（守卫/session 闭环/授权码交换/State 防 CSRF/持久化/安全传输）。

关键词库：**闭环 / 独立封装 / 统一规范 / 自动化 / 标准化 / 类型安全 / 零代码重构 / 按需构建 / 多端复用 / 双向通信 / 契约驱动**。

### 4.2 别学 CSISIP 的（面试漏洞预警）

- "摒弃定制化项目自建通信框架" 与 "构建 Socket 协议与 BFF 层" 自相矛盾 → 追问即穿帮
- "多仓库代码治理" 实为单仓库 monorepo → 术语误用，面试官一听就知道
- "前后端一体化部署于 Render" 无 Docker/CI 细节支撑 → 追问部署步骤答不上
- **包装只允许"重述真实能力"，不允许"虚构不存在的能力"**。我们把"没有的东西"写进简历，要同步把它做出来（见第二节路线）。

### 4.3 我们的项目重写版（对标 CSISIP 风格，全部真实）

**项目概述（一版）**：
> 真白 Mashiro —— 基于 TypeScript 全栈的 AI 面试陪练一体化系统：Electron 桌宠前端 + MCP 服务端 + Headless 云端三端形态，Monorepo 治理（pnpm + Turborepo），BFF 网关统一调度 widget 服务，AI 能力以 MCP 协议开放给任意支持工具，依托 CI/CD 双流水线实现「独立开发 — 按需构建 — 运维部署」完整闭环。

**成果条目（每条=真实能力+标准术语）**：

1. **Monorepo 工程化体系**：pnpm workspace + Turborepo 组织桌面端/服务端/共享包，任务编排与构建缓存，CI 门禁全自动（90+ 单测、coverage、类型检查、lint、bundle 一致性、基准评测），显著降低迭代回归风险。（Phase 1 落地后成立）

2. **契约驱动的双层 API 体系**：以 zod 定义 widget REST API 与 Electron IPC 边界 schema，两端共享类型、自动生成类型安全 SDK；路由注册表集中治理（lib/routes），废弃手写 fetch 与无校验 IPC 入参，接口改动编译期暴露。

3. **AI 协议化开放架构**：独立封装 MCP 服务端，把面试/学习/复习/求职/巡检等能力以标准化协议暴露，可被 Claude Code / Cline 等任意 MCP 客户端接入；配套插件系统（动态加载/沙箱隔离/权限审批）与 Agent 操作审批链，实现能力按需插拔与安全可控。

4. **轻量服务鉴权**（Phase 3 升级为 OAuth2.1 + PKCE 多端 SSO）：widget 服务令牌鉴权 + 会话管理 + 审批链闭环，桌面端 / MCP / headless 三端统一接入；State 防 CSRF、令牌安全传输。

5. **环境与密钥分层管理**：config 层多环境（dev/prod/test）注入、启动校验、密钥隔离不入库，零代码重构完成全系统环境切换。

6. **框架无关组件层**（Phase 3 可选）：面板 UI 抽为原生 ESM 组件库，多端复用，零框架依赖。

7. **部署闭环**：CI 三流水线 —— 桌面端 electron-builder 发布（nsis+portable）、headless 服务 Docker 化部署 Render、MCP 包发布；`独立开发 → 按需构建 → 运维部署` 全自动。

8. **我们独有、CSISIP 没有的加分项**（重点包装这些）：
   - **AI 评测体系**：双层评测（真实模型端到端 LLM-as-Judge/TRACe/CRAG + mock harness pass^k/goalState/taxonomy）+ 判官金标校验 + web 任务基准——详见 `docs/AI评测体系包装与升级.md`（⚠️ 必须先按该文档补齐规模/门禁/基线再写进简历，不能只写"mock-LLM 基准门禁"）
   - **产品闭环**：模拟面试 → 弱项回流 → 学习清单 → FSRS 复习 → 掌握度 → 二次面试针对性出题，九环审计报告（docs/ 有完整审计文档，面试可展示）
   - **多模态**：Live2D 桌宠 + 语音包 + sherpa-onnx 本地 ASR + VAD 实时打断
   - **防御性工程**：原子化 JSON 写入、自动备份、崩溃恢复、prompt 注入防护、依赖审计门禁

### 4.4 面试防御：每个包装点背后要能讲出细节

规则：简历上每个名词，面试时能说出"在哪个文件、什么机制、踩过什么坑"。
- 「契约驱动」→ `lib/routes/router.mjs` 路由注册表 + zod schema 校验入参（Phase 2 后）
- 「CI 门禁」→ ci.yml 每个 step 的作用 + 为什么加 bundle 一致性检查（防改源码忘 build）
- 「MCP 开放架构」→ mcp-server.mjs 的工具清单、与 widget 服务的路由映射
- 「审批链」→ ask-user.mjs 的审批超时/否决机制（commit 历史里有"审批超时否决"修复，是真实故事）
- 「基准评测」→ benchmark-agent.mjs 的 pass^3 判定逻辑、mock LLM 方案
- 准备一个 3 分钟演示脚本：启动桌宠 → 开始面试 → 暴露弱项 → 学习清单 → 复习 → 展示 CI 全绿截图

**关键提醒**：简历是"已落地能力清单"不是"规划书"。每条包装必须先落地（哪怕最小实现），再写进简历；4.3 里标注 Phase 的条目，未落地前不要出现在简历上。
