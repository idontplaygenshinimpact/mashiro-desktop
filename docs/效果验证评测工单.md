# 效果验证评测工单（把"设计断言"变"效果数据"）

> 背景（客观审视结论）：项目多项"优势"是**设计断言、无评测数据**——薄弱点闭环效果、混合检索命中率、前缀缓存收益、自评门禁提升，全部没有数据证明。本工单补齐效果验证，把"设计有洞察"升级为"效果有数据"。
> 基础设施：LLM-as-Judge 已有（eval-scoring.ts:60 `judgeAnswer`）、benchmark/reports 目录已有（eval_summary.csv）、trace_llm 已记录 role/inputTokens/outputTokens/endpoint（llm.ts:395-396）。

## 任务 1（P0，~1.5 天）：混合检索评测集 + 命中率对比

**背景**：个人学习知识库工单任务 1 明确要建评测集（20-30 个真实问题对比 BM25-only vs 混合），但上线时未做——"命中率提升"是断言不是数据。

**评测集构建**（从真实使用数据提取）：
- 素材来源：chat_history 用户问题 + study_notes 追问段落（真实查询形态）+ 薄弱点 topic（学习需求形态）；
- 20-30 个问题，覆盖四类：
  - 精确匹配（版本号/函数名/专有名词，BM25 应该赢）；
  - 语义匹配（同义改写，向量应该赢）；
  - 跨文档聚合（"状态机"散落多篇）；
  - 追问指向（"useState 和 store 的关系"——追问段落专属）。

**评测方法**：
1. 每个问题分别跑 `searchParagraphs`（BM25-only，关向量）与 `searchParagraphsReranked`（混合+rerank）取 top5；
2. LLM-as-Judge 判定 top5 相关性（复用 judgeAnswer 或轻量 judge：`{relevant: bool}`，maxTokens 收紧）；
3. 人工抽检 5 个（防 judge 盲区）。

**指标**：top5 命中率（≥1 条相关 + 相关条数）、MRR、**混合 vs BM25-only 增益**。

**决策门禁**（写进报告）：
- 混合显著高（命中率 +15%+）→ 保留向量；
- 差不多（±5%）→ 向量降级讨论（省 ~100MB 内存）；
- 更低 → 排查（切分/融合/模型）。

**输出**：`benchmark/eval-report-hybrid.md`（评测集 + 结果表 + 决策结论）；`npm test` 新增评测集加载测试（数据可复跑）。

## 任务 2（P1，~1 天）：薄弱点闭环效果评测

**背景**：摸排（self_assess）→ 消费（面试/复习/讲解/逛网）→ 清除——"31 条薄弱点驱动学习"没有数据。

**评测方法**（全部从现有表统计，零埋点）：
1. **清除率**：origin="self_assess" 的薄弱点中，已清除（weak_points 表删除/memory.clearWeakPoint）的比例 + 平均清除周期；
2. **与被动积累对比**：self_assess vs 面试/复习来源的清除率——摸排是否"有效建立画像"；
3. **消费命中**：近 N 次讲解生成中 getWeakPointContext 命中次数（trace_llm role=agent 的 prompt 是否含薄弱点上下文——可抽样统计）；
4. **逛网定向**：nowcoder-surf 归档中"薄弱点定向 N 篇"的篇数占比。

**输出**：`benchmark/eval-report-weakpoint.md`（清除率 + 周期 + 消费命中 + 结论：摸排有效性）。

## 任务 3（P1，~1 天）：前缀缓存收益实测

**背景**：splitExplain 主文恒定命中 DeepSeek 前缀缓存——"省 token"是设计断言，无实测。

**实现**：
1. 扩展 trace_llm：新增 `cached_tokens` 字段（DeepSeek API usage 的 prompt_cache_hit_tokens / prompt_tokens_details——llm.ts 记录处补抓，:395-396 旁）；
2. 统计讲解/追问链路的缓存命中：缓存 token 占比 + 成本节省（按 token 单价折算）；
3. 对照：无缓存策略的调用（如 agent 主循环 messages 每次都变）的命中率——验证"主文恒定"策略的实际增益。

**输出**：`benchmark/eval-report-prefix-cache.md`（命中率 + 节省成本）；`npm test` 新增用例（cached_tokens 记录）。

## 任务 4（P2，~1 天）：自评门禁效果（A/B 对比）

**背景**：自评门禁（Reflexion）"不足自动补一轮"——质量提升无对比数据。

**评测方法**：
1. 抽样 10 个历史讲解（自评上线前后各 5）；
2. 统一 judgeAnswer 质量评分（覆盖时间线/对比/边界≥3/追问 3-5 四项）；
3. 统计：自评补全触发率（trace 里 self-judge role 调用 + 补全发生）、补全后四项达标率提升、成本增量（每次讲解 +1 次自评 ~0.001 元）。

**输出**：`benchmark/eval-report-selfjudge.md`（触发率 + 达标率 + 成本）。
