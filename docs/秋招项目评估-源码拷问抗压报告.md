## 二、能扛住拷问的深度点（面试官深挖也不怕的硬货）

### 方向 A：agent 开发 —— 最匹配，深度点最密集

**A1. deny-first + 会话级状态机的权限系统**（`lib/agent.mjs:102-175`）
- 统一入口 `checkToolPermission`：会话级 deny 硬拦截（防 LLM 变参重试无限弹审批）→ auto 写审计账本 → confirm 走 `requestApproval`（**超时=拒绝**）→ 拒绝记 `markSessionDenied`
- `job_apply` 被排除在会话级 auto-approve 之外（`permission.mjs`），审计账本区分 user / auto-approve-session / timeout / deny
- 新对话重置会话级状态（`:526-531`，防常驻进程批准延续到后续对话）
- 追问预案："为什么审批超时默认拒绝？"→ 与 deny-first 哲学一致，防静默放行；"账本为什么不存参数值？"→ 隐私防护，SENSITIVE_TOOLS 脱敏。

**A2. 工具循环的防死循环/无进展保护**（`agent.mjs:572-676`）
- 同参数 **sha1 哈希**连续调用上限 3（不是工具名计数——注释明确解释 80 字符截断会误杀合法流水线）；每工具连续失败上限 3（独立计数，跨工具不误伤）
- 全局 deadline 180s 在**每次长工具调用后补查**（审批/ask_user 可达 60-120s，轮间检查会漏）
- 被跳过工具自动补 `role:"tool"` 占位响应（`:599-607`），保证消息序列对 provider 合法——这是很多人会漏的协议细节
- 追问预案："为什么同一轮多个 tool_calls 要串行？"——⚠️ 见雷点 R2，这里必须诚实。

**A3. 提示注入 + SSRF 纵深防御**（`lib/prompt-guard.mjs` + `lib/fetch-page.mjs`）
- 所有外部内容（搜索标题/页面正文/RAG 命中/子代理结果/MCP 返回）统一 `<untrusted_data>` 包裹 + system prompt 声明 + 注入模式正则检测
- fetch-page 是唯一抓取入口：DNS 全解析防 rebinding、IPv4 映射/NAT64 展开、子资源静态快速校验
- **无 shell/exec 类工具**——LLM 无任意命令执行面，这是最容易被问也最安全的点
- 追问预案："标记包裹能防住吗？"→ 诚实回答：这是 Claude Code/OpenHands 同款纵深防御，不是强隔离，真正的兜底是工具权限 + 无执行类工具。

**A4. MCP 客户端/服务端双向 + 自环去重**（`agent.mjs:741-748`）
- `mcp__mashiro__*` 与内置 TOOLS 同名工具被过滤，避免"同一能力两套实现行为分叉"——这个细节很少人想到，是能讲出东西的点

**A5. LLM 客户端 failover 工程细节**（`lib/llm.mjs:112-247`）
- AbortError（网关挂起）**不重试直接切备用端点**；429/5xx 才走 1/2/3s 退避重试
- 空响应（HTTP 200 + 空 content）视为可重试，且自动 **max_tokens 翻倍**（推理模型预算不足）
- 流式 `delivered` 标记：已交付内容后出错不重试（防 UI 重复）
- SSE 手写解析（TextDecoder + 分帧 + 末尾 flush），`extractJson` 是带括号配平的健壮 JSON 提取

### 方向 B：agent 全栈 —— 广度惊人，架构设计有真东西

**B1. 插件协议 + 加载器**（`lib/plugin-loader.mjs` + `plugins/plugin-template/`）
- manifest 声明（panel/settings/init/health）+ 注册期失败隔离（单插件加载失败不阻断其他插件）+ 路由顺序防遮蔽
- 设置命名空间 `plg_<id>_` 前缀 + manifest 白名单；市场安装有 zip-slip/路径穿越多层防护
- Skills 热重载用 `?v=` 参数绕 ESM 模块缓存——这是真实踩坑后的工程细节

**B2. HTTP 服务安全基线**（`widget.mjs:385-411`）
- 仅绑定 127.0.0.1 + CORS 白名单（file:// Origin:null / localhost）+ 全 API Bearer token（token 随机生成落盘）+ 1MB 请求体上限 + EADDRINUSE 端口回退
- 渲染层 token 由主进程 `webRequest.onBeforeSendHeaders` 透明注入（`desktop/main.mjs:1298-1300`）

**B3. MCP Server 用官方 SDK + zod**，工具结果截断回填，被外部 agent（Claude Code 等）真实可调

**B4. 调度器三态 + 自动熔断 + heartbeat**（`lib/scheduler.mjs`）；巡检带每日 token 预算（防超支）

**B5. 【已完成的加分项】zod 契约层（此前评估遗漏，2026-08-27 实测补录）**
- `lib/contracts/` 7 个 zod schema（chat/common/interview/misc/review/sse/study）+ `lib/routes/contract.mjs` 的 `withContract` 实现 + SSE 事件 union（`createSSEPush` 统一 4 处散装推送）
- git 历史完整：Wave 0（骨架）→ Wave 1（SSE 契约统一）→ Wave 2（15 个高频路由挂 input/output 契约）→ Wave 3（前后端类型化 + **收编 117 处硬编码直连**）→ 配套测试（ChatOutput 字段改名漂移拦截用例）
- 前端产物 `desktop/kanban-api.d.ts` + api-client.mjs 统一入口
- **面试讲法**："API 边界用 zod 定义 input/output 契约，路由注册时 withContract 自动校验，SSE 事件用 union 类型约束；字段改名有漂移拦截测试——接口改动编译期暴露。"注意与 ts-rest 区分（自研轻量方案，未用 ts-rest），并诚实说明 checkJs 类型覆盖仍只限 4 个文件（见附一）

### 方向 C：前端 —— 深度点有，但方向匹配度最低

**C1. Electron 安全基线真配置**（`desktop/main.mjs:152-161`）：contextIsolation + nodeIntegration:false + sandbox:true；preload 只暴露 50+ 具名 invoke 包装，**没有**把 ipcRenderer 整个丢出去

**C2. SSE 并发隔离**（`main.mjs:422-454`）：`channel:${token}` 动态事件名定向推送——注释记录"曾广播串流"的真实修复史；TextDecoder stream + \n\n 分帧手写解析

**C3. 透明窗口 + WebGL 踩坑**：`transparent:true` + PIXI clearColor(0,0,0,0)；`showInactive` 避免抢焦点（透明窗 isFocused 永久 true 的坑）；koffi FFI 直调 GetForegroundWindow/GetWindowRect 做毫秒级全屏检测（替代慢速 PowerShell）

**C4. 本地 ASR 管线**：worker 线程串行化（同步推理阻塞主进程的历史卡顿根因）+ transferable 零拷贝 + AudioWorklet（注释含"Electron43 inputBuffer 全零"实测理由）+ VAD 能量阈值裁头尾

**C5. CSP 有明确权衡记录**：index.html 的 `unsafe-eval` 带注释解释（PixiJS 运行时 Function 构造，去掉白屏）；panel.html 是严格 CSP

### 方向 D：数据/算法/评测（所有方向的公共弹药）

**D1. FSRS 正确调库**（`lib/review.mjs:4,117`）：真用 ts-fsrs（FSRS-6 默认参数），Grade 映射 [Again,Hard,Good,Easy]、状态 JSON 持久化 + 拆列索引 + 事务更新。追问"w 参数为什么用默认？"→ 诚实回答：FSRS 需 1000+ 复习样本个性化拟合，个人项目用默认是合理取舍——**答得上=真懂，答不上=贴标签**

**D2. 学习闭环血缘真落库**（`review.mjs:121-138`）：复习答错 → 薄弱点 failCount+1 → 学习清单 → 复习卡，测试直接断言 DB 状态（`tests/review.test.mjs`）

**D3. quiz 洗牌双坐标系 bug 修复史**（`quiz.mjs:186-203`）：展示位 → 原序映射再判分，注释记录"75% 答对被判错"的历史 bug——现成的"讲一个你踩过的坑"素材

**D4. 检索工程 trade-off**（`rag.mjs:246-296`）：trigram 适配中文（无空格分词）+ 2 字词 LIKE 兜底 + 标题命中 +0.5 提权压 URL 噪声——有测试专门断言

**D5. 评测方法论理念正**（`scripts/benchmark.mjs`）：客观判定为权威（code/predict 真跑 node 子进程比对），LLM-as-Judge 双评只做辅助，judge-gold 金标校验判官一致性（exactRate 80%），消融固定 seed 洗牌 + 单题 hash 缓存

**D6. 测试质量真实**（`tests/helpers.mjs:13-23`）：临时 DB 隔离 + 只 mock LLM 不 mock 业务逻辑——"测了等于没测"的测试在这个项目里基本不存在

## 三、扛不住的雷点（按致命度排序——面试官最可能戳穿的）

### 🔴 R1【最致命】README 数字过期/不可复现，一问报告就穿
- "337 道可自动判题" → 实测 281；"13/13" → 报告是 19/19；"10/10" → 当前客观题只有 5 道
- **面试官打法**："你 README 写 337 道能判题，现在多少？""13/13 是哪次跑的，报告在哪？"
- **应对**：面试前 48 小时重跑 `npm run bench` + `npm run bench:agent`，把 README 数字全部更新为当前实测值；或者把 README 数字改成"以 benchmark/reports 为准"并附链接。**这是零成本、收益最大的修复。**

### 🔴 R2【agent 方向】"并行"是假的：spawn_subagent 宣称并行、实现串行
- schema 写"一次可调用多个 spawn_subagent 实现并行"（`schemas.mjs:303`），但主循环对多个 tool_calls 是**顺序 await**（`agent.mjs:608-671`），subagent.mjs 自己注释"顺序执行（非并行）"
- **面试官打法**："你 README 说子代理并行，代码里哪一行是并行？"——答不出当场减分
- **应对**：二选一：① 改成 `Promise.all` 真并行（改动小，注意 tool 结果回填顺序与 provider 的 tool_call_id 对应）；② 面试话术："工具串行执行是为了结果按序回填、上下文稳定，并行是设计目标、当前实现是串行"——**诚实交代比被戳穿强**，但①更优

### 🔴 R3【agent 方向】agent 对话主循环非流式，"逐 token"只存在于讲解链路
- `chatWithAgent` 用非流式 `llmChat`（`agent.mjs:771`），回复整轮结束才返回；流式 `llmChatStream` 只在 ai.mjs 讲解/追问/归并用
- **应对**：主动讲清楚两套链路的分工（对话=工具循环决策、讲解=长文流式渲染），这反而显专业；不要笼统说"全流式"

### 🔴 R4【全方向】origin 溯源防污染只做了一半（可复现的注入漏洞）
- `getTrustedWeakPoints` 过滤了 untrusted（`memory.mjs:206-213`），但 **`getProfileSummary()` 直接用未过滤的 mem.weakPoints**（`:348-357`），`injectCuratedIntoPrompt` 也不过滤（`:404-409`）→ 爬虫提炼的伪知识点仍可进 system prompt 画像
- **应对**：把这两处改成走 `getTrustedWeakPoints` / 过滤 origin——**改动 10 行内，消掉一个真漏洞**

### 🔴 R5【全栈方向】"插件失败隔离"语义夸大：运行期异常会 process.exit 带崩宿主
- `widget.mjs:106-117` 未捕获异常/拒绝 → `process.exit(1)`（注释说明靠桌面守护重启）。这是**故意的崩溃重启策略**，但与 README"失败隔离"宣传不符
- **应对**：面试时主动区分："注册期隔离 + 运行期 fail-fast 崩溃重启（守护进程拉起）"，并说明为什么选崩溃重启（挂起状态难恢复，重启最干净）——这个解释是自洽的，但要主动讲

### 🔴 R6【全方向】消融实验的负结果打脸"全链路 prompt 工程"卖点
- `ablation-latest.json`：裸 prompt judge **88** vs 全链路 **80**（Δ=-8）；docs 里宣传的"61→81"是另一口径且 n=8、cacheHits=8（全是缓存复用）
- **面试官打法**："你的评测证明你的工程化有价值吗？"——数字上恰恰相反
- **应对**：① 诚实讲负结果 + 你的解读（README 已有"ΔCRAG -17pt 部分来自判官长文随机波动"的诚实分析，这是加分姿势）；② 面试前补跑一次 sample 足够大的消融，重新校准口径；③ 别把"61→81"这种口径混乱的数字写进简历

### 🔴 R7【前端方向】渲染层"直连 8899"与"主进程转发"叙事矛盾
- api-client.mjs 收编了 120+ 处直连；panel-study.js:1707 连**流式端点**都直接 fetch（靠 main 的 webRequest 注入 token）
- **应对**：讲清三层架构：交互流式走 IPC 转发（并发隔离）→ 缓存/常规 API 走渲染层直连（webRequest 注入 token）→ 后端 CORS+token 双保险。能自圆其说，但要主动讲，别让面试官发现你在回避

### 🔴 R8【前端方向】若干具体硬伤
- `voice-pack.mjs:143` 硬编码本机绝对路径 `D:\hfut\file\Videopro\exp01\...\ffplay.exe`（有 env/probe 兜底，但路径泄露本机信息且换机必走兜底）
- index.html CSP 带 `unsafe-eval`（有注释解释，可辩护；但两窗口 CSP 不一致会被问）
- panel-jobs.js 爬虫字段未转义 + `data-id` 属性注入面（XSS 面未清零）
- tsconfig.desktop.json 只覆盖 4 个文件，"类型化"名不副实
- **16k 重采样没实现**：VAD 按 `sampleRate||16000` 假设，pcm-worklet 原样转发——README 声称"16k 采样率兜底重采样"是虚的
- Live2D 深度疑似停留在 README 复述层：只有结论注释（sharedTicker/deltaTime），无防御代码

### 🔴 R9【数据方向】RAG 是"纸面能力"：默认关闭、agent 几乎不用
- `ragEnabled()` 默认 false；关闭时工具直接从 schema 隐藏（`agent.mjs:750-754`）；rag.mjs:13 自认"search_knowledge 历史仅 1 次调用"
- **应对**：要么默认开启让它真被用起来，要么诚实表述"检索型任务才用 RAG（出题/刷题），讲解刻意不用 RAG（黑箱不可解释）"——README 其实有这段决策档案，面试引用它即可

### 🔴 R10【数据方向】STaR 评分无数字校验：脏 LLM 输出 → NaN → 回流静默失效
- `interview.mjs:522-523`：`(scores.tech+...+reflect)/5` 无 isFinite/clamp，字符串/缺维度 → NaN，`NaN<60` 恒 false → 薄弱点回流静默丢
