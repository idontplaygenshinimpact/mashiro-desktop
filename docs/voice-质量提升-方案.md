# 真白语音质量提升方案（失真的根因与治理）

> 背景：重合成虽然修好了尾部截断（tail 11%→61%），但用户反馈"失真，不符合原本的语音"。已用 git 恢复原版资产（idle-1/idle-2/idle-long-1）。
> 本文档是**真正的质量提升方案**——不是妥协，是把"重合成为什么失真"的根因挖出来并治理。

---

## 1. 失真的根因（代码实锤）

**合成选优只有一个维度：内容完整度（cov）。**

旧逻辑（`synth-mashiro-long.py` 采样循环）：
- 每子句采样 6~12 次，选 `cov`（whisper 2-gram 覆盖）最高的样本
- **完全没有音色（voice_sim）和节奏（pacing）维度**

后果：一个"内容念全了、但音色漂移 / 语速飞"的样本，`cov` 照样高 → 照样胜出 → 写入资产。**评测体系（score-voices）有三维指标，但合成选优只用了一维**——评测与合成不同标，这就是"修好了内容却失真"的结构性原因。

佐证：idle-2 重合成 cov 48%/tail 40%（内容都不全）→ 得分低被保留；而"内容 90% 音色 0.75"的样本会胜出 → 用户听到"声音不像真白了"。

## 2. 质量提升方案（合成与评测同标）

### 2.1 合成选优四维评分（已实现 ✅）

`synth-mashiro-long.py` 采样循环现在与 `voice:score` 同口径：

| 维度 | 计算 | 权重 | 达标线 |
|---|---|---|---|
| 内容完整度 | whisper 2-gram 覆盖（cov） | 0.35 | ≥0.55 |
| **音色相似度** | resemblyzer 嵌入 vs 真白锚点（`data/mashiro-anchor.npy`）余弦 | 0.30 | **≥0.88** |
| 节奏 | ms/字（110-170 满分） | 0.20 | 参与评分 |
| 尾部覆盖 | 期望末尾 vs 转写末尾 2-gram | 0.15 | ≥0.4（尾块 0.55） |

- 音色不达标（<0.88）**不允许提前达标**（继续采样）；全部采样后仍不达标 → 打印 `cov/sim/尾部` 定位信息
- 输出从"内容 OK"升级为"内容+音色+节奏 OK 才算 OK"
- resemblyzer CPU 推理（避免与 ctranslate2 cuDNN 冲突，score-voices 同款规避）

### 2.2 参数稳定化（下一步）

- 当前采样是 top_p/temperature **微扫描碰运气**（[1.0,0.95,1.0,0.9,1.0,0.85] × [1.0,0.9,1.1,1.0,1.2,0.95]）
- 四维选优就位后，扫描的作用从"碰内容运气"变成"在内容+音色+节奏空间里搜索"——扫描保留但**收窄范围**（社区经验：top_k 5-15 / temperature 0.6-0.9 更稳），待实验定
- 目标：高质量文本一次命中（少扫描 = 少漂移 = 一致性）

### 2.3 ref 体系（音色漂移的主因，下一步）

- 音色由 ref 音频锚定。当前单一 ref（ref-clean-A.wav，声纹 0.962）
- **情绪匹配 ref 多套**：不同场景（鼓励/安慰/吐槽/日常）用不同情绪的 ref——GPT-SoVITS 的 ref 情绪直接影响生成情感与音色一致性
- **更长的 ref（8-15s）**：ref 越长声纹越稳（社区共识）
- ref 变更后重跑 `voice:score --compare` 验证声纹不降

### 2.4 训练侧（根本提升，成本高，列为远期）

- mashiro3（1472 段 e20）已解决长句截断；音色上限由数据决定
- 若追求更高自然度：更多干声数据 + 更长 SoVITS 训练；**不在当前范围**

### 2.5 验证闭环（合成即评测）

```
合成（四维选优）→ voice:score（同标三维 + 评级 A-D）→ 全 A 才入资产 → audit（尾部/泄漏）
```
- 合成脚本与 score-voices **共用同一套指标函数**（clean_text/锚点/resemblyzer 调用），杜绝"评测说好、听感不对"的再次脱节

## 3. 实验验证计划

1. `npm run voice:synth -- --only idle`（新四维选优）→ 观察每块打印的 `sim` 值
2. `npm run voice:score` → idle 三个文件的 voice_sim 应 ≥0.9（与原版同水平），pacing 110-170
3. `npm run voice:audit` → tail 达标
4. **人工对比**：新合成 vs git 原版（用户最终裁决"像不像真白"）
5. 若 sim 达标但听感仍差 → 进入 2.3（ref 情绪匹配），再实验

## 4. 纪律（防再犯）

- **存量资产不整条盲跑重合成**（git 可回退，但重合成=换新样本，有漂移风险）
- 重合成前先备份（`git stash` / 复制到 backups/）
- 合成质量以"四维达标 + score 全 A"为门槛，**人工抽样听感复核**（声线是产品资产，机器指标兜底 + 人耳终审）

## 6. 实验结论（2026-08-26，四维选优首跑）

**数据**（新配方重合成 idle 场景）：
- 音色 sim：0.897~0.958（全部贴近真白锚点，**四维选优的音色约束生效**）
- 内容 cov：34~65%（各块），尾部 0~11%（idle-long-1 尾块仍丢）

**核心发现——模型固有矛盾**：对 idle 这批文本，**"内容完整（含尾词）"与"音色保真"在当前权重下互斥**：
- 上一次"tail 修到 61%"的版本，音色漂移（用户听出失真）——选优无音色约束
- 本次"音色 0.92+"的版本，尾部又丢——模型对该文本的尾词生成本身不稳定
- 即：**原版资产（历史多轮采样产物）已是当前权重+ref 下的最佳平衡**，重合成无法同时满足两者

**结论与纪律**：
1. 存量资产保持原版，不盲跑重合成（本次双保险回退成功）
2. 四维选优**保留**——用于未来新增语音/场景（合成即评测，杜绝"内容全但失真"胜出）
3. 质量提升的真正下一站：**ref 体系实验**（GPT 阶段生成质量受 ref 情绪/风格锚定）：
   - 情绪匹配 ref 多套（鼓励/安慰/日常分 ref）
   - 更长 ref（8-15s，社区共识声纹更稳）
   - ref 换后跑 `voice:score --compare` 验证声纹不降 + 内容覆盖提升
4. 若 ref 实验仍不能同时满足内容+音色 → 训练侧（更长 SoVITS、更干净数据）为唯一根治路径，列为远期
