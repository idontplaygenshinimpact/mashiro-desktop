### Monorepo（pnpm workspace）迁移关注点（子代理观察，非改）
1. **`#lib/*`/`#root/*` 是根包私有别名**，plugins 消费 73 处；plugins 独立成包后会失去解析目标 → 需显式依赖或改相对路径
2. **checkJs 覆盖不全**（desktop/、plugins/ 未纳入 typecheck）→ 拆包时要重划各包 tsconfig/类型契约
3. **原生/预编译模块**（koffi、sherpa-onnx-node、transformers、electron 二进制、playwright）在 pnpm 符号链接布局 + `npmRebuild:false` + `asarUnpack: plugins/**` 下的二进制携带需验证
4. **esbuild 跨包 resolve 基准改变**，可能重复打包
5. **发布编排**：prepare-publish 临时改写根 package.json 的机制在多包并行 publish 下需重设计
6. **check-renderer 的 mtime 门禁**在 CI 缓存/并行构建下易伪阳性

## 2. API 契约层与类型边界（子代理核实）

### 2.1 路由注册表：三级分发，无校验库
- 注册器 `lib/routes/router.mjs:4-23`：`createRouter()` → `route(pathname, method, fn)` / `resolve` / `size()`（method 可省略=任意；首个命中优先）。**全项目 142 处 `router.route` 汇聚点**，纯字符串注册表，无 zod/JOI
- 宿主 `widget.mjs`：CORS 白名单 → Bearer 门禁（除 /api/health）→ `router.resolve` 分发（未命中 404）
- 核心域 `lib/routes/core.mjs`（依赖注入取数）＋ 业务域 `plugins/job-hunter/server.mjs`（聚合 12 个 routes 文件）
- **入参校验：全手写 ad-hoc**（typeof / Number.isInteger+区间 / JSON.parse try-catch / item?.id），无第三方校验库
- 代表性路由（30+）：`/api/health|widget-data|chat|chat/sessions|messages|session|chat-stream|stats|observability|refresh|approval-pending|approval|run-discover|patrol-config|patrol-run|progress|schedule|plugins*|backup|backups|backups/restore|study-plan|study-detail-stream|study-generate|study-check|interview/start|answer|end|history|status|interview-notes|jobs/profile|jobs|jobs/recommended|jobs/collect|oj/problems|oj/collect-all-stream|zhenti|focus/start|status|review/due|submit|explain-stream|knowledge/search|ask|settings/*|greeting|dashboard`

### 2.2 契约即测试（雏形）
- `tests/routes-registry.test.mjs`：断言 55 条原版路径齐全（防拆分丢路由）+ 9 条 GET/POST 方法门控 + 注册总数 ≥100 + 15 条新增
- **性质：只护"路由存在+方法正确"，不测入参/响应 schema**——回归完备性清单，未到契约层

### 2.3 数据库层
- SQLite（node:sqlite DatabaseSync，WAL + foreign_keys），**23 张表**（settings/interests/chat_history/weak_points/mastered_points/interview_history/study_plan_items/review_cards/card_reviews/kp_mastery/job_posts/focus_sessions/schedule_events/scheduled_jobs…）
- **无独立 schema 文件**：建表 SQL 内联 db.mjs，行类型未结构化（fsrs/options/dims 为 JSON 字符串列），迁移 try/catch ALTER 幂等
- `lib/atomic-json.mjs`：写 .tmp 再 rename（防半写崩溃），readJsonSafe 回退 .tmp

### 2.4 IPC 边界/类型映射
- `desktop/preload.js`（140 行）：contextBridge 暴露 `window.kanban.*` **约 60 个方法**（widget:/interview:/review:/window:/app:/music:/mascot:/speech:/resume/import:parse-file 等），走 ipcRenderer.invoke
- `desktop/main.mjs`：**62 个 ipcMain.handle**（194-1092）；preload 的 widget:* 大多转成 main.mjs 的 widgetGet/widgetPost → **IPC 是 widget REST 的薄转发层**；流式走 `widget:*-stream` + `__streamToken` 定向 channel
- **类型声明：无**（全项目 0 个 .d.ts；preload 无 @typedef；tsconfig 不含 desktop/renderer → 渲染层零类型）

### 2.5 渲染层取数：双轨混用，直连 HTTP 为主
- IPC `window.kanban` 197 处（panel-study.js 流式、panel-chat.js chatStream）
- **直连 fetch 123 处**，硬编码 `http://127.0.0.1:8899/api/...`（renderer 硬编码 8899 达 120 次，panel-jobs 56/panel-rest 37/…）；**直连不带 Authorization**，靠主进程 webRequest onBeforeSendHeaders 自动注入 Bearer
- 直连流式：panel-rest.js:843 对 oj/collect-all-stream 用 fetch body.getReader() 手解析（非 EventSource）
- **无统一客户端**：只有 main.mjs widgetGet/widgetPost + preload streamPromise；其余分散写死

### 2.6 schema/校验库：无
- package.json 无 zod/joi/yup/valibot；grep 无 `from "zod"`；唯一 validate() 在 lib/tool-policy.mjs（工具权限 profile，与 HTTP 无关）

### 2.7 SSE/流式形态
- 自定义 `text/event-stream`，统一 `data: <JSON>\n\n` + `type` 字段（start/tool_start/tool_done/tool_error/delta/done/error/progress）
- 端点：chat-stream、study-detail/append/consolidate/cluster-stream、review/explain-stream、oj/collect-all-stream
- **事件形状无单一 schema**，两端硬编码对齐（preload streamPromise 只认 done/error/delta/start，jsonMode 认 ok）

### 2.8 契约层接入点（子代理建议，观察）
1. **首选 `lib/routes/router.mjs`**：给 route() 加可选 input/output schema（zod），在 widget.mjs:408 resolve 后统一校验返回 400，向后兼容
2. **流式事件提为契约**：type:delta/done/error/start/progress 负载 → zod discriminated union，core.mjs push() 与各插件 send() 复用（SSE 最易字段漂移）
3. **preload 白名单类型化**：补 .d.ts/@typedef（window.kanban 全量签名）+ 把 desktop/**、renderer 加进 tsconfig include
4. **收编 120 处直连 8899**：收敛到带 base URL+认证说明的轻 client（或统一走 window.kanban）
5. **db.mjs schema ↔ 类型**：zod infer 为每张表定义行类型供复用
6. 两端共享类型当前缺：一个被 lib/routes + preload + renderer 同时引用的共享类型包（TS 源或 .d.ts + zod），三处现各自硬编码，字段漂移只能手测

## 3. 鉴权与环境配置

### 3.1 widget 服务鉴权（子代理核实）
- **静态 Bearer Token，非 OAuth/JWT**：`lib/widget-core.mjs:74-88` `loadOrCreateToken()` 用 randomUUID 写 `data/widget-token.json`；**永不轮换/过期/无客户端绑定**
- 优先级：`MIANSHI_TOKEN` env > widget-token.json > 生成落盘（widget.mjs:113-117）
- 校验：`checkBearerAuth()` 精确字符串相等（非恒定时间比较，本地回环风险低）
- 接入：仅 `/api/*`（除 `/api/health` 豁免）强制；CORS 白名单只放行本机回环/null origin（⚠️ `corsOrigin = reqOrigin || "*"` 在 Origin=null 时可能回落 `*`）
- 客户端：桌面主进程 widgetFetch 显式带头 + 渲染层 webRequest onBeforeSendHeaders 注入；MCP/headless 共享**同一 token**（无每端独立凭据）
- **无鉴权审计日志**（仅 401 应答；trace.mjs 只记审批决策，非网络鉴权）

### 3.2 审批链/权限（子代理核实，与网络鉴权是**两套独立机制**）
- `lib/permission.mjs`：请求分级 → `requestApproval` 挂起；**deny-first 超时 60s 默认拒绝**；session 级 approve/deny Set，`job_apply` 禁会话放行；同工具并发合并一次询问
- agent 侧 `lib/agent.mjs:105-148`：isSessionDenied 硬拦截 → requestApproval → 用户决策
- 与 UI 联动：widget 暴露 `GET /api/approval-pending` + `POST /api/approval`{toolName,allow,session}；ask-user（120s 超时）同通道
- 语义分层：**OAuth 管"能否连服务"，审批管"能否执行动作"**，可叠加（升级方向）

### 3.3 配置与多环境（子代理核实）
- `config.mjs`（131 行）：LLM 供应商（OpenCode Go + 官方 failover + 多 provider）、model/outputDir/navTimeout/solveMaxTokens/compactBudget
- **手写 dotenv 解析，无 NODE_ENV 分层**（单 .env + 进程环境变量 + opencode auth.json 兜底）；`assertConfig()` 启动自检无 key exit(1)
- **41+ 环境变量**（LLM/鉴权/路径/备份/压缩/语音/抓取/测试隔离，共 grep 114 处）
- `.env` 仅 1 个变量 DEEPSEEK_API_KEY，已 gitignore（.gitignore:5）

### 3.4 数据与备份（子代理核实）
- `lib/backup.mjs`：createBackup 先 checkpoint 合并 WAL，备份 SQLite + output/study_notes + progress.json 到 `data/backups/<ts>_<reason>/`；**maxBackups=10、minInterval=24h**；**模块本身无定时器**（由调用方按间隔触发）；markRestore → applyPendingRestore 重启生效
- data/：mianshi.db(+wal/shm)、widget-token/platform-accounts/nowcoder-cookie/mascot-model/window-state/mcp-servers/knowledge-trees 等 JSON + 日志 + 调试产物

### 3.5 多端身份（子代理核实）
- **无多端身份体系**：platform-accounts.mjs 只管理平台 cookie 登录态 + 投递策略（日限额 10、最小间隔 30s）；edge-session/chrome-cookies 是**本机浏览器登录态复用**（Playwright），非 OAuth
- **OAuth/OIDC/PKCE/state/code_challenge 全项目 0 命中**

### 3.6 密钥安全（子代理核实）
- 密钥均磁盘明文但 **gitignore 全覆盖**（data/* 忽略 + 4 个静态资产放行；.env:5 绝不提交；实测定序验证）
- **preload 白名单不暴露 process.env/密钥/cookie**（contextBridge `window.kanban.*`）；token 注入全在主进程；渲染层 CSP connect-src 仅本机 8899/self/file

### 3.7 鉴权升级前提（子代理建议，观察）
1. 先立"身份源"：本地单用户需引入账号实体；可复用 widget-token.json 作 **bootstrap 凭据**
2. 让 widget(8899) 兼任**本机授权服务器**，面板/MCP/headless 各自为 OAuth client（改动收敛、不引外部 IdP）
3. **PKCE 必配**（public client 无 secret，S256 code_verifier/challenge + state 防 CSRF），并堵住 CORS 回落 `*` 缺口
4. **token 生命周期**：短周期 access + 长期 refresh（可撤销），替代永久文件 token
5. **client 分层**：桌面走授权码+PKCE；headless/MCP 走 **device flow + PKCE**（对应现有共享 Bearer 场景，实现每端独立凭据可单独吊销）
6. **多端 SSO**：widget 为唯一 IdP，token 带客户端归属+scope；与 permission 审批层正交叠加
7. 加固：恒定时间比较 + AuthN 审计日志（现状断层）

## 4. 部署与 headless 化

### 4.1 MCP 服务形态（子代理核实）
- **transport = stdio**（`mcp-server.mjs:5-6,206-207`，`StdioServerTransport`，注释"Claude Code 配置后自动连接"），**无 SSE/HTTP transport**
- 暴露 **9 个工具**：search_posts / solve_question / get_study_plan / start_interview / get_personal_profile / get_jobs_status / get_schedule_events / get_study_progress / get_project_archives，实现均 `await import("./lib/*.mjs")`
- **可脱离桌面独立运行 ✅**：`bin/mashiro-mcp.mjs` 独立入口，无 Electron 依赖，默认数据目录 `~/.mashiro/`

### 4.2 widget 服务形态（子代理核实）
- **纯 Node HTTP 服务**（`node http`，绑定 **127.0.0.1**，widget.mjs:436，非硬编码可配）；端口 `MIANSHI_PORT || 8899`，EADDRINUSE 回退 3 次写 `data/widget-port.json`
- **可独立进程 ✅**；桌面壳 `desktop/main.mjs` 只是 spawn 并守护它（widget-server.mjs 探测 /api/health，挂了拉起；30 秒 ensure）
- CLI/env：`--no-notify`、`MIANSHI_PORT`、`MIANSHI_TOKEN`、`MIANSHI_DISABLE_PATROL=1`、`MIANSHI_DISABLE_BACKGROUND=1`；**无 `--headless` 等进程级开关**
- 鉴权：`/api/*`（除 health）须 `Authorization: Bearer <token>`；CORS 白名单只放行本地回环/null origin

### 4.3 headless 可行性（子代理核实，关键结论）
- **lib/ 对 Electron 依赖 = 0**（grep `require('electron')` 无命中）；**koffi 只在 desktop/**（foreground.mjs、main.mjs 注释）
- sherpa-onnx 仅在 `lib/speech.mjs:29`（语音输入，可换 whisper）；playwright 在 lib/ 4 处（edge-session/fetch-page/oj/zhenti，多动态加载）→ 仅爬取类工具触发
- **核心（widget + MCP + agent）完全可脱离 Electron 跑纯 Node**

### 4.4 文档与生态（子代理核实）
- `docs/plugin-architecture.md`（183 行）：面向外部开发者的正式插件方案（manifest.json + manifestVersion + api.min 版本契约、分发形态 A 仓库/B npm/C 市场、4 阶段迁移）
- README 头部有**徽章行**：License(MIT)/CI(GHA badge)/npm 版本/Node≥22/**Tests 754+**/Windows 10/11——现有可视化基础好
- CHANGELOG.md 存在（86 行），SemVer，标注"未发布正式 release"

### 4.5 部署痕迹与产物（子代理核实）
- 🔴 根目录无 Dockerfile/render.yaml/vercel.json/fly.toml/Procfile
- release/ 产物被 gitignore；存在两套历史构建产物（193MB portable+Setup 与 789MB 版，均 0.1.0）→ 历史构建配置不统一
- sharp 被打进 asar.unpacked（依赖链带入，非显式配置）

### 4.6 运行入口梳理（子代理核实）
- `desktop/main.mjs`（Electron 壳）→ 守护 spawn `widget.mjs`（独立 Node :8899）→ lib/ agent 核心；widget 再 spawn `discover.mjs` 巡检
- `run.mjs` / `discover.mjs` 是独立 CLI 爬虫批处理入口（不经 Electron）；**注意 package.json 的 `run` 脚本 = `node run.mjs`（命令行爬取），不是启动桌宠**

### 4.7 云部署最小改造（子代理建议，观察）
1. 形态：widget HTTP → Render Web Service（需把监听地址/CORS 参数化：#436 硬编码 127.0.0.1）；MCP → 新增 SSE/StreamableHTTP transport 或保持本地 stdio CLI
2. 新增 Dockerfile（node:22-slim，`npm ci --omit=dev`）+ render.yaml；`files` 清单只留 bin/lib/mcp-server/config/data，**排除 desktop/models/assets/skills**
3. 爬取类工具触发 playwright → MVP 先部署不涉浏览器的纯 agent/MCP 能力，爬取标"可选浏览器后端"
4. 语音(koffi)/Live2D/notify 不进镜像；后台定时用 `MIANSHI_DISABLE_BACKGROUND=1`+`MIANSHI_DISABLE_PATROL=1`
5. 持久化：Render Disk 挂 `MIANSHI_DATA_DIR`/`MIANSHI_OUTPUT_DIR`（已有 env）；密钥走 Render secret envs
6. 一句话：**核心是纯 Node HTTP 服务，无需 Electron；剩的是工程接线**
