# 真白 Mashiro：项目愿景总结与路线图

> 本文档总结从「对标 CSISIP 全栈综合系统」开始，经全量摸排、多次概念澄清与方向收敛后，为这个项目形成的**完整未来愿景**。
> 每一层都标注：来源对话、真实存量、缺口、优先级判断（✅ 优先 / 🕐 放后 / ❌ 不做）。
> 配套文档：工程化升级与简历包装指南 / 工程化现状台账 / AI评测体系包装与升级 / phase2-contracts-方案 / phase4-headless部署-方案 / lingchat-借鉴分析 / audit-report / audit-ui-func-prompt

---

## 一、愿景总览（分四层）

```
┌ L3 生态开放：桌宠外观/声线包、受信任面板宿主、MCP 分发（部分已完成）
├ L2 形态拓展：桌宠 → 多 Agent 桌面伴侣（CC/OpenCode/Codex）+ 自主桌宠内核  ★主线，具稀缺性
├ L1 能力深化：双层评测体系扩容、表达渲染管线、AI 技能场景化（已有 6 技能底座）
└ L0 工程化外衣：契约层(优先) / Monorepo(放后) / PKCE(放后) / 云部署(不做)
```

---

## 二、逐层详解

### L0 工程化外衣（对标 CSISIP 的包装层）

| 项 | 结论 | 理由（经多轮诚实评估） |
|---|---|---|
| **契约层（Phase 2）** | ✅ 第一优先，方案已出（phase2-contracts-方案.md） | 切口最干净（router.mjs 142 处汇聚点）；信号真实（改字段 typecheck 红）；前瞻多端（面板/插件/云/伴侣都吃契约） |
| **双层 AI 评测体系** | ✅ 优先，独立路线（AI评测体系包装与升级.md） | 方法论已强（Judge/TRACe/CRAG/金标），只差规模/指标/消融基线/可视化；可产出真实数字（61→81 型 Δ） |
| **Monorepo（Phase 1）** | 🕐 放后 | 不是功能是组织方式；6 个迁移坑（#lib 别名进 plugins 等）；只对包装有意义，风险最高 |
| **PKCE SSO（Phase 3）** | 🕐 放后 | 无多端身份需求；成本最高（要引入身份源）；先立好契约/插件权限再说 |
| **云部署/headless（Phase 4）** | ❌ 降级为可选，优先不做 | 无真实用户=演示级=零稀缺性，面试官一句话拆穿；**真实部分已兑现**：release.yml 的 npm 发布 MCP 包（`npm i -g mashiro-mcp` 别人真能用） |

### L1 能力深化（AI 产品向）

- **双层评测扩容**：questions 14→60+、web-tasks 1→20+、金标 10→30+；补 pass@1/EM/成本/延迟/回归门禁/README 徽章；消融 A/B 拿真实 Δ
- **表达渲染管线**：借鉴 LingChat（lingchat-借鉴分析.md）——LLM 输出分段（情绪/动作/语音稿分离）→ Live2D 表情 + 气泡 + TTS 同步。存量已够（Live2D/voice-pack/emotions.mjs），缺"由 agent 决策驱动的映射管线"

### L2 形态拓展：桌宠 → 多 Agent 伴侣（主线，具稀缺性）

三种形态（用户澄清后的真实意图）：
- **A. 能力接入 MCP**：✅ **已完成**（mcp-server.mjs 9 工具 + npm 发布 + README 声明"可接入任意支持 MCP 的工具"）
- **B. 桌宠当伴侣 UI**：🗺 规划中——桌宠作为 CC/OpenCode/Codex 的**桌面伴侣**（显示状态/播报/TTS/可视化交互）。技术底座：各工具 machine-readable 输出（CC `--output-format stream-json`、Codex `--json`+hooks、OpenCode TS Plugin API）→ 推送到 widget(127.0.0.1:8899，Bearer 已有) → Live2D 气泡/语音/面板。**Claude Code 先行**（MCP 已闭环 + stream-json 最成熟）
- **C. 官方插件**：🕐 暂缓（每工具一套，成本高，先走 B）

### 自主桌宠内核（把 B 做实需要的 4 块）

| 诉求 | 真实现状（已核实） | 缺口 |
|---|---|---|
| 强化桌宠属性 | Live2D + 气泡 + voice-pack + emotions.mjs（稀缺情绪设计） | 表达渲染管线（agent 决策 → 表情/动作/语音） |
| 独立 agent 能力 | lib/agent.mjs 完整 agent 循环 + 审批 + tool-policy | **事件驱动内核**（现为请求-响应式，非 proactive）★最大缺环 |
| 多场景 skill | lib/skills.mjs + skills/ **已有 6 技能**（company-intel/interview-warmup/resume-coach/tech-compare/github-repo/frontend-cheatsheet），SKILL.md 声明式 + skill.mjs 动态工具 + hooks | 事件→场景→skill 的装配与动态切换 |
| 自主决策+自学习 | lib/loop.mjs 规则决策引擎"当前该做什么"（明确"LLM 只提炼、决策用规则"）+ dreaming.mjs 夜间记忆巩固 + fsrs + trace | **从结果反思闭环**（trace 失败模式 → 调整 skill/提示词） |

**落地切片**：P0 事件驱动内核 → P1 skill 场景装配 → P2 表达渲染管线 → P3 反思闭环（小而真，不当宣传词）

### L3 生态开放（经收敛后剩下的真价值）

- ✅ **桌宠外观/声线包**（用户看得见，mascot-models + voice-pack 已有底座，补打包/分发）
- 🕐 **受信任面板宿主**（manifest 已有 panel 声明，缺渲染层动态装配 + 声明式权限；**用现成 8 个 tab 当验证负载**，不做 iframe 沙箱、不吹开放市场）
- ❌ **桌宠整体独立**（无第二宿主=伪需求）；❌ **开放插件市场/data 页签**（无生态=画饼）；❌ **面板第三方页签当卖点**（同前）

## 三、演进脉络（关键转折）

1. **CSISIP 对标** → 想"包装"，产出《工程化升级与简历包装指南》（Phase 0-4）
2. **被质疑"评测简陋"** → 核实发现双层评测很专业，只缺规模 → 《AI评测体系包装与升级》
3. **全量摸排** → 4 主题子代理并行 → 《工程化现状台账》（事实底座，7 条战略发现）
4. **概念澄清三连**（Monorepo / 契约 / 云部署 / 插件化）→ 一次次挤水分，诚实下调低信号项
5. **用户澄清真实意图**（把桌宠带上 CC/OpenCode/Codex）→ 愿景从"工程化包装"转向"产品形态拓展"
6. **深化为自主桌宠** → 发现仓库存量（agent/skills/loop/dreaming）→ 得出"缺的是串起来的层，不是零件"

## 四、最终推荐路线（按展示价值 × 岗位匹配 × 成本）

```
第 1 优先  契约层（Phase 2，已出方案，可开工）
第 2 优先  评测体系扩容 + 消融基线（独立路线，可并行）
第 3 优先  事件驱动内核（P0，桌宠伴侣 + 自主桌宠的共同地基）→ Claude Code 伴侣试点（形态 B）
第 4 优先  skill 场景装配（P1）→ 表达渲染管线（P2）→ 反思闭环（P3）
收尾善后  MCP 分发文档化（真实闭环显性化，半天）
放后可选  Monorepo / PKCE / 受信任面板宿主 / 外观声线包
明确不做  云部署 / 桌宠整体独立 / 开放插件市场 / 面板第三方页签
```
