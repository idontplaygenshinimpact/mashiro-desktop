# 讲解质量增强工单（知识时效性 + 生成策略）

> 背景证据：对话/清单讲解「从 GPT-3.5 梳理 LLM 与 Agent 演进」实测生成文档存在三类问题——
> ① **知识过时**：时间线停在 2025 年初，缺 DeepSeek R1/o3 推理时工具调用/GPT-5.1/Claude Opus 4.5/Gemini 3/A2A/ACP 等 2025-2026 节点；
> ② **概念错误**：o1 机制被写成"Test-Time Training"（实为 RL 训练推理链 + 推理时计算扩展，TTT 是另一条研究线）；
> ③ **结构缺陷**：RAG 时间线/BM25 对比/架构迭代等深度维度靠追问才补上（单次长文生成前紧后松）。
>
> 根因分层：**第一层（最根本）= 知识时效性**——模型知识截止 + `solveQuestion` 链路不联网（`web_search` 工具存在但未接入，agent.mjs:258-259 可用、ai.ts:497-561 不用）；第二层 = 生成策略（单次长文）；第三层 = 闭环缺失（追问补全不回流存档）。
>
> 决策边界：项目"讲解不用 RAG"（黑箱 vs 可解释）针对**本地知识库**；**联网搜索带来源链接、可溯源**，不违背该决策——本工单全部手段保持"每点可溯源"。

---

## 任务 1（P0，核心，~1 天）：时效性主题识别 + 联网检索注入

**目标**：讲解"强时效性主题"时，先检索最新资料再生成——先解决"内容对不对、新不新"。

**实现**：
1. **识别**：新增 `TIME_SENSITIVE_TOPIC_RE`（演进/最新/2025/2026/现状/趋势/对比/发布/版本/里程碑/时间线/发展/路线图…），组合词化（复用 `match-utils.mjs` 的 `kwHit` 模式，防单字误命中——参照 `ALGO_TOPIC_WORDS` ai.ts:433 的写法）；
2. **注入**：命中时在 `solveQuestionImpl`（ai.ts:497）prompt 组装前调 `searchWeb(query, { limit: 5 })`（web-search.mjs:133）检索 2-3 个 query（题目主题 + "2025 2026 最新"），结果 `{title, url, snippet}` 注入 prompt 的【最新资料参考】段（**带来源链接**，讲解"来源："字段已有，可溯源）；
3. **降级**：搜索失败/无结果 → 不注入，讲解照常（catch 不阻断，与 ensureMcp 同款容错）；
4. **防注入**：检索结果 `wrapUntrusted`（外部数据，prompt-guard.mjs:9-17）。

**测试**（`tests/helpers.mjs` 加 `setMockSearchResults`，复用 `setMockPages` 模式；`tests/ai.test.mjs` 新增）：
- ① 时效性题命中 → prompt 含检索结果 + 来源链接；
- ② 非时效性题（如"事件循环"）→ searchWeb 不被调用（零网络）；
- ③ 搜索失败 → 降级不炸、讲解照常；
- ④ 检索结果被 wrapUntrusted 包裹。

**验收**：同题「LLM 与 Agent 演进」生成对比——含 2025-2026 节点（DeepSeek R1 / o3 推理时工具调用 / GPT-5.1 / Claude Opus 4.5 / Gemini 3 / A2A / ACP）；o1 机制表述正确（RL + 推理时计算，非 TTT）；来源可溯源；搜索失败讲解不中断。

## 任务 2（P1，~1 天）：追问回流存档（闭环，讲解越用越好）

**现状**：`solveAppendStream`（ai.ts:267）+ `consolidateStudyStream`（ai.ts:337）已存在，但"追问补全 → 整合成完整文档"要**用户主动触发**；`followup-cache.mjs`（追问缓存）、`study-notes-learn.mjs`（存档转清单）已有。

**实现**：
1. 追问补全（solveAppendStream 产物）自动回流 `study_notes/{topic}.md`（或 chat_solutions 存档），幂等合并；
2. `solveQuestionImpl` 生成前查同题存档：有则基于存档增强生成（存档 = 自己验证过的高质量产出，可溯源，不违背 RAG 决策）；
3. 复用 followup-cache 判重（同题追问过的直接取缓存）。

**验收**：同题二次讲解基于增强版存档（含上次追问补全内容）；存档更新幂等（重复追问不重复追加）；`npm test` 新增回流用例。

## 任务 3（P1，~1-1.5 天）：两阶段生成（大纲先行）

**现状**：`solveQuestionImpl` 单次调用生成全文（ai.ts:497-561）——长文前紧后松、深度不均（用户实测症状）。

**实现**：
1. 命中任务 1 识别（或新增 `STRUCTURED_TOPIC_RE`：梳理/演进/对比/体系类）→ 先非流式出大纲（章节 + 每节要点）→ 再逐节生成 → 拼接；
2. 流式兼容：`solveQuestionStream` 的 onChunk 语义保持（大纲阶段非流式，正文阶段流式）；
3. 大纲注入正文 prompt（防节间重复/遗漏）。

**验收**：同题两次生成对比——深度分布均匀（原理/时间线/对比表不再靠追问补）；流式链路无回归（sse-contract 测试绿）。

---

## 任务 4（P2，~0.5 天）：生成后自评门禁（Reflexion 式）

**现状**：`eval-scoring.mjs` 的 `judgeAnswer`（LLM-as-Judge）已有，仅用于评测。

**实现**：讲解生成后轻量自评（是否覆盖时间线/对比/边界 ≥3/追问 3-5 个），不足自动补一轮（复用 solveAppendStream 机制）。

**验收**：自评触发补全的用例；成本可控（自评 maxTokens 收紧）。

## 排期与依赖

```
任务 1（P0 时效性检索）──┬──> 任务 2（追问回流，依赖题型识别）
                         └──> 任务 3（两阶段生成，依赖题型识别）
任务 4（自评门禁，独立，可并行）
```

与 `docs/编排能力缺口工单.md` 的关系：任务 1 = T4 记忆检索注入的**讲解场景变体**（外部检索而非本地）；任务 3 = T1 规划状态机（大纲=计划、逐节=执行）；任务 4 = T2 失败反思。**讲解链路是编排能力缺口的第一个落地场景。**

## 红线

1. 每任务一个 commit，先加后改、保持兼容（ESM import / API 响应结构 / SSE 契约不变）；
2. 验收 = typecheck 0 error + lint 0 error + `npm test` 全绿（回归跑 2 次）；
3. **不违背"讲解不用 RAG"决策**：只注入"带来源链接的联网检索结果"与"自己验证过的历史存档"，不注入本地知识库黑箱内容；
4. 外部数据一律 `wrapUntrusted`；搜索/存档失败降级不阻断讲解；
5. 面试叙事沉淀：问题（用户实测文档）→ 证据（ai.ts:497-561 不联网）→ 方案（检索注入/回流/两阶段/自评）→ 取舍（可溯源 vs 黑箱）→ 验证（同题对比）。
