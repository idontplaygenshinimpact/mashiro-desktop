好的，这道题是前端面试中最高频的「手写源码」类题目之一。它表面考的是 `Promise.all` 的 API 记忆，实际上考的是你对 **Promise 状态机**、**异步时序**、**错误处理策略** 的底层理解。

## 题目

> 手写 `promiseAll(promises)`，要求与 `Promise.all` 行为完全一致：全部成功则返回按传入顺序排列的结果数组；任一失败则整体 reject，且返回 reason 为第一个失败的 promise 的 rejection reason。

---

### 结论

核心思路：**创建计数器 + 结果数组（按索引填充）+ 在微任务中检查是否全部完成**；当任意一个 promise reject 时，立即 reject 整个返回的 promise。

---

### 原理

要写出行为完全一致的 `promiseAll`，必须理解 `Promise.all` 的五个底层机制，缺一不可：

1. **输入是「可迭代对象」，不限于数组**
   `Promise.all` 接受任何 iterable（数组、Set、Map、字符串等）。它内部会先对输入做一次迭代（用 `for...of` 或 `Array.from`），拿到所有元素后再统一处理。手写时也要考虑：传入 `null` / `undefined` 会在迭代时抛 `TypeError`，正确行为是返回一个 **rejected promise**（而不是同步抛错）。

2. **所有 promise 是「并行发起」的，不是顺序执行**
   遍历到每一项时会立即调用 `Promise.resolve(item)` 把它包装成 promise，并立刻挂上 `.then` —— 这一步相当于「启动」了它。千万不要在 `.then` 里拿到 resolve 再启动下一个，那就变成串行执行了。

3. **结果数组按「输入下标」填充，而不是按「完成顺序」填充**
   先完成的 promise 可能排在后边，后完成的可能排在前边。所以需要预先分配 `new Array(length)` 并用 `result[index] = value` 来保持顺序。不能用 `push`，否则结果顺序会乱。

4. **用计数器判断是否全部完成**
   因为结果数组里的空位会被访问自动跳过，所以不能靠 `result.length === total` 来判断完成（稀疏数组的 length 一开始就对）。正确的做法是记一个 `remaining` 计数器，每完成一个 `result[index]` 填充后就 `remaining--`，当 `remaining === 0` 时整体 resolve。

5. **失败是「竞速」的：第一个 reject 决定整体结果，其余 promise 的后续结果被忽略**
   当任意一个 promise reject 时，`Promise.all` 返回的 promise 立即进入 rejected 状态。但注意：**其他 promise 并不会被取消**，它们仍然继续执行完，只是其结果不会再被采纳（同时要注意这个 reject 回调不能重复触发，否则会报 "Promise already settled" 警告）。所以需要在内部用一个 `settled` 标记，一旦整体 settle 就不再做任何操作。

---

### 实现

以下是完整实现，包含空数组、普通值混合、类型转换等所有边界行为的处理：

```javascript
/**
 * 手写 Promise.all，行为与原生 Promise.all 一致
 * @param {Iterable} iterable 可迭代对象（数组 / Set / 字符串等）
 * @returns {Promise} 返回一个新的 Promise
 */
function promiseAll(iterable) {
  // 关键点1：参数必须是可迭代对象，否则返回 rejected promise
  return new Promise((resolve, reject) => {
    // 转成数组，内部已验证是 iterable
    // 如果这里抛错，会被 new Promise 自动捕获并变成 rejected
    const items = Array.from(iterable);

    // 边界：空数组 -> 直接 resolve 空数组
    if (items.length === 0) {
      resolve([]);
      return;
    }

    const results = new Array(items.length); // 预分配，保持顺序
    let remaining = items.length;            // 计数器
    let settled = false;                     // 整体是否已确定

    for (let i = 0; i < items.length; i++) {
      // 关键点2：用 Promise.resolve 将普通值也包装成 promise
      // 关键点3：挂上 .then 时立即启动该 promise（并行）
      Promise.resolve(items[i]).then(
        (value) => {
          if (settled) return;  // 整体已失败，忽略后续结果
          
          results[i] = value;   // 按索引填充，保持顺序
          remaining--;

          // 关键点4：所有完成才整体 resolve
          if (remaining === 0) {
            settled = true;
            resolve(results);
          }
        },
        (reason) => {
          // 关键点5：任一失败 -> 整体立即 reject（只触发一次）
          if (settled) return;
          settled = true;
          reject(reason);
        }
      );
    }
  });
}

// 测试用例
const p1 = Promise.resolve(1);
const p2 = 2; // 普通值
const p3 = new Promise((res) => setTimeout(() => res(3), 100));

promiseAll([p1, p2, p3]).then((res) => {
  console.log(res); // [1, 2, 3] —— 保持顺序，哪怕 p3 最慢
});

promiseAll([]).then((res) => {
  console.log(res); // [] —— 空数组直接 resolve
});

promiseAll(null).catch((err) => {
  console.log(err instanceof TypeError); // true —— 参数非法返回 rejected
});
```

function promiseAll<T>(iterable: Iterable<T | PromiseLike<T>>): Promise<T[]> {
  return new Promise((resolve, reject) => {
    const items = Array.from(iterable);
    
    if (items.length === 0) {
      resolve([]);
      return;
    }

    const results: T[] = new Array(items.length);
    let remaining = items.length;
    let settled = false;

          results[i] = value;

            settled = true;
            resolve(results);
          }
        },
        (reason) => {
          if (settled) return;
          settled = true;
          reject(reason);
        }
      );
    }
  });
}

### 边界与追问

#### 边界情况

| 场景 | 行为 | 说明 |
|------|------|------|
| 传入空数组 | `resolve([])` | 原生的 `Promise.all([])` 也是直接 resolve 空数组 |
| 传入 `null` / `undefined` | `reject(TypeError)` | 因为无法迭代，手写时利用 `Array.from` 自动触发 |
| 数组里混有普通值 | 自动包装成 promise | 用 `Promise.resolve(item)` 统一处理 |
| 多个 promise 同时失败 | 整体采纳**第一个** reject 的 reason | 其余 reject 被忽略（`settled` 标记） |
| 失败后其他 promise 还在运行 | 无法取消，结果被忽略 | 这是 JS 单线程模型的特性，可对比 fetch + AbortController |

#### 性能注意事项

- `Promise.all` 是**无并发限制**的：它会同时启动所有 promise。如果传入 10 万个 promise，会一次性创建大量微任务，可能造成性能问题或内存压力。实际项目里遇到这种情况，需要自己实现**并发限制**（比如 `p-limit` 库，或手写一个 `asyncPool`）。
- 每个 `Promise.resolve(items[i])` 都会创建一层微任务包装，如果数组里有大量**已经是 promise** 的值，会多一次微任务开销，但这是原生 `Promise.all` 也有的行为，无额外代价。

#### 兼容性

- `Promise.all` 是 ES6 标准，IE 不支持。手写版本可以配合 Promise polyfill 在旧浏览器使用 —— 前提是 `Promise` 本身存在。
- 需要注意：原生 `Promise.all` 要求参数是 iterable，而**某些旧的 polyfill（如 `ES6-Promise` 的早期版本）只支持数组**。手写的 `Array.from` 版本已经兼容所有 iterable。

#### 面试官追问 & 参考回答

**追问 1：`Promise.all` 是「同时执行」还是「顺序执行」？如果我想限制并发数怎么办？**

> 所有 promise 在调用 `Promise.all` 的那一刻**同步启动**，本质是「并行发起」—— 但 JS 是单线程的，所以准确说是「并发调度」，而不是「并行计算」。真正的并行需要 worker 线程。想限制并发数，需要自己写一个「任务池」：维护一个执行队列，每次最多跑 N 个，跑完一个从队列里取下一个，全部完成后再 resolve。这种实现被称为 `Promise.mapLimit` 或 `asyncPool`。

**追问 2：如果 `promises` 数组中有一个不是 Promise 而是普通对象 `{ then() { throw new Error('x') } }` 会怎样？**

> 这就是「thenable」对象。`Promise.resolve` 会尝试调用它的 `then` 方法（即「摊平 thenable」）。如果 `then` 里抛错，该 promise 会被 reject，`promiseAll` 整体 reject。这跟原生 `Promise.all` 的行为一致——**传入的 thenable 会被完全展开**，即使是多层的嵌套 thenable 也会递归展平。

**追问 3：如果让我实现 `Promise.allSettled`（全部完成才返回，不 reject），思路有什么不同？**

> 核心差异在两点：① 不设置「整体失败短路」，每个 promise 的成功和失败结果都要收集；② 每个结果从「值」变成「状态对象」——`{ status: 'fulfilled', value }` 或 `{ status: 'rejected', reason }`。其余机制相同：计数器 + 索引填充。更进阶的变形 `Promise.race` 则只需要在第一个 settle 时 resolve/reject，不需要计数器。

**追问 4：手动实现 `Promise.all` 时，`settled` 标记真的是必要的吗？**

> 必要。一旦整体进入 rejected 状态，后续其他 promise 完成时如果仍然执行 `resolve(results)` 或再次 `reject`，虽然不会改变返回的 promise 状态（状态已锁定），但仍然会执行一遍回调逻辑，多出无意义的微任务，而且如果我们的实现里在 resolve 后还操作了外部状态，就可能产生副作用。加上 `settled` 标记让逻辑更严谨，能防止「重复 settle」的编程错误。
