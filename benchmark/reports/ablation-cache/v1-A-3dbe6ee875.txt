## 事件循环中的宏任务与微任务

浏览器中的 JavaScript 是单线程的，所有任务都需要排队执行。事件循环（Event Loop）负责调度任务，核心是区分两类任务：

- **宏任务（MacroTask）**：由宿主环境发起，比如 `script` 整体代码、`setTimeout`、`setInterval`、I/O、UI 渲染、事件回调等。每个宏任务执行完后，会检查并清空微任务队列。
- **微任务（MicroTask）**：由 JavaScript 引擎发起，比如 `Promise.then`、`queueMicrotask`、`MutationObserver` 等。微任务会在当前宏任务结束后、下一个宏任务开始前全部执行。

执行流程大致是：

1. 执行一个宏任务（例如整段 `<script>`）；
2. 执行过程中遇到微任务，将其放入微任务队列；
3. 当前宏任务执行完毕，立即清空所有微任务；
4. 清空微任务后，浏览器可能会进行渲染；
5. 从宏任务队列中取出下一个宏任务执行，重复上述过程。

关键点：**微任务优先于下一个宏任务执行**，而且微任务中新增的微任务会在当前微任务队列清空之前一并执行。

## 代码输出顺序分析

```js
console.log(1);
setTimeout(() => console.log(2), 0);
Promise.resolve().then(() => console.log(3));
console.log(4);
```

逐行分析：

1. `console.log(1)` —— 同步代码，直接输出 **1**。
2. `setTimeout(() => console.log(2), 0)` —— 注册一个宏任务，回调被放入宏任务队列，等待当前宏任务结束后执行。
3. `Promise.resolve().then(() => console.log(3))` —— 注册一个微任务，回调被放入微任务队列。
4. `console.log(4)` —— 同步代码，直接输出 **4**。

当前宏任务（整段 script）执行完毕，此时输出为：`1 4`。

接下来事件循环会先清空微任务队列，所以 `console.log(3)` 执行，输出 **3**。

微任务队列清空后，再从宏任务队列取出 `setTimeout` 的回调，执行 `console.log(2)`，输出 **2**。

因此最终输出顺序是：

```
1
4
3
2
```

## 更直观的流程

```
执行 script 宏任务
  ├─ 输出 1
  ├─ 遇到 setTimeout，挂起，0ms 后放入宏任务队列
  ├─ 遇到 Promise.then，放入微任务队列
  └─ 输出 4
script 宏任务结束
  ↓
清空微任务队列
  └─ 输出 3
  ↓
取出下一个宏任务（setTimeout 回调）
  └─ 输出 2
```

所以答案是：**1、4、3、2**。微任务总是先于下一个宏任务执行，即使 `setTimeout` 的延迟是 0ms。
